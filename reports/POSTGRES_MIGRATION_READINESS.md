# PostgreSQL 전환 준비도 보고서

## 기준

- 운영 논리 DB: `sermon_db`
- 테스트 논리 DB: `sermon_db_test`
- 현재 운영 DB: `data/bible.db` (SQLite)
- 인증 DB: `auth.sqlite3` (SQLite)
- PostgreSQL 전환: 미적용

## 현재 운영 데이터

운영 SQLite는 약 500MB이며, 성경 본문·원어·RAG 데이터가 포함되어 있다.
주요 행 수는 다음과 같다.

| 영역 | 테이블 | 행 수 |
|---|---|---:|
| 성경 | `passages` | 31,098 |
| RAG | `rag_embeddings` | 31,098 |
| 원어 | `original_word_notes` | 412,309 |
| 원어 | `original_pronunciations` | 306,785 |
| 그리스어 | `greek_nt_tokens` | 137,554 |
| 그리스어 | `greek_nt_verses` | 7,939 |
| 본문 비교 | `textual_variants` | 6,934 |

교리 수집 테이블은 구조만 존재하거나 초기 데이터 상태이다. 교리 원본은 MinIO에 보존하되 SQLite→PostgreSQL 전환과 함께 자동 승격하지 않는다.

## 타입 매핑 초안

| SQLite | PostgreSQL | 검토 사항 |
|---|---|---|
| `INTEGER PRIMARY KEY` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | 기존 ID 보존 여부 결정 |
| `TEXT` | `TEXT` | 길이·정규화 정책 확인 |
| `REAL` | `DOUBLE PRECISION` | 임베딩 norm 등 수치 비교 |
| `BLOB` | `BYTEA` | 벡터 blob 변환 검증 |
| JSON 문자열 | `JSONB` 후보 | 원문 문자열 호환성 유지 필요 |
| SQLite partial unique index | PostgreSQL partial unique index | predicate 동일성 검증 |
| SQLite trigger | PostgreSQL trigger/function | 오류 메시지와 조건 회귀 필요 |

## 전환 순서

1. `sermon_db_test`에 빈 스키마 생성
2. 기존 SQLite 스키마와 PostgreSQL DDL 비교
3. 소량 fixture로 타입·제약·트리거 검증
4. 테스트 DB에 읽기 전용 데이터 복제
5. 행 수·SHA-256·핵심 검색 결과 비교
6. 백업과 rollback 검증
7. feature flag 뒤에 선택적 PostgreSQL adapter 연결
8. 운영 전환 리허설
9. 승인 후 `sermon_db` 전환

## 중단 조건

- SQLite와 PostgreSQL의 행 수가 다름
- 핵심 레코드의 해시가 다름
- 성경 본문·원어·RAG 검색 결과가 기준선보다 나빠짐
- 교리 문서의 출처 metadata가 유실됨
- SQLite rollback 백업이 검증되지 않음
- 기존 애플리케이션이 PostgreSQL 장애 시 기능 단위 오류를 처리하지 못함

## Rollback

- PostgreSQL adapter feature flag 비활성화
- 기존 SQLite DB를 운영 원본으로 유지
- PostgreSQL 데이터 삭제는 자동 실행하지 않음
- 전환 중 생성된 PostgreSQL 데이터는 감사 후 별도 정리
- SQLite 백업 복원은 기존 backup/restore 흐름으로 수행

## 현재 판정

`설계 준비 완료 — 마이그레이션 미실행`

현재 앱은 SQLite를 계속 사용한다. `sermon_db`와 `sermon_db_test`는 향후 PostgreSQL 검증·전환용 논리 이름으로만 사용한다.
